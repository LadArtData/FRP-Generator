Drop FRP Studio into APEX

Same pattern you used for the validate component: upload the existing HTML as a Shared Component (Static Application File), reference it from a single APEX page, and wire its fetch calls to PL/SQL via AJAX callbacks. No rewriting the UI in APEX-native pages.

★
If your validate component pattern was different (e.g. a Page Template or a Plug-in), tell me and I'll re-spec to match exactly. Defaults below are the most common APEX-shared-component path for a self-contained HTML/JS app.

Step 1 — Upload the HTML as a Shared Component

1.1Static Application FileApp Builder → Shared Components
  • Open your APEX app → Shared Components → Static Application Files.
  • Click Upload File.
  • Upload FRP Studio.html exactly as it sits in this project — the Google Fonts CDN link works fine, no other external assets to bundle.
  • After upload, APEX gives you a substitution string like #APP_FILES#FRP%20Studio.html. Copy it.
1.2Host pageSingle blank APEX page
  • Create a new page, type Blank Page, name it FRP Studio.
  • Add a single Static Content region. Set its source to:
<iframe
  src="#APP_FILES#FRP%20Studio.html"
  style="width:100%;height:calc(100vh - 90px);border:0"
  allow="clipboard-read;clipboard-write">
</iframe>

An iframe is the cleanest container — keeps the Studio's CSS isolated from APEX Universal Theme and avoids ID/class collisions. Same pattern most embedded Claude artifacts use.

Step 2 — Wire fetch() to PL/SQL via AJAX callbacks

Right now the Studio's buttons are mocked (sample data, simulated progress). Replace those with calls to APEX AJAX callbacks defined on the host page.

Example AJAX Callback body

-- Process: LIBRARY_LIST  (Type: AJAX Callback)
DECLARE
  l_out CLOB;
BEGIN
  APEX_JSON.initialize_clob_output;
  APEX_JSON.open_array;
  FOR r IN (
    SELECT doc_id, filename, prefix, deal_status,
           client_name, ingested_at, size_bytes
      FROM frp_docs
     ORDER BY ingested_at DESC
     FETCH FIRST 200 ROWS ONLY
  ) LOOP
    APEX_JSON.open_object;
    APEX_JSON.write('doc_id',      r.doc_id);
    APEX_JSON.write('filename',    r.filename);
    APEX_JSON.write('prefix',      r.prefix);
    APEX_JSON.write('deal_status', r.deal_status);
    APEX_JSON.write('client',      r.client_name);
    APEX_JSON.write('ingested_at', r.ingested_at);
    APEX_JSON.write('size_bytes',  r.size_bytes);
    APEX_JSON.close_object;
  END LOOP;
  APEX_JSON.close_array;
  l_out := APEX_JSON.get_clob_output;
  APEX_JSON.free_output;
  HTP.p(l_out);
END;

In the Studio HTML — the bridge

Add a tiny shim near the top of FRP Studio.html so its existing fetch calls find APEX. Because it's iframed, it talks to the parent page's APEX session via window.parent.apex.server.process:

const apexCall = (name, data) =>
  new Promise((res, rej) => {
    const apex = (window.parent && window.parent.apex) || window.apex;
    if (!apex) return rej(new Error('APEX bridge not available'));
    apex.server.process(name, { x01: JSON.stringify(data || {}) }, {
      success: (r) => res(r),
      error:   (e) => rej(e)
    });
  });

// then replace mock data calls with:
const docs = await apexCall('LIBRARY_LIST');
renderLibrary(docs);

In each AJAX Callback, read the payload with APEX_APPLICATION.G_X01 and parse with APEX_JSON.parse.

Step 3 — Authentication & session

  • The iframe inherits the parent APEX session automatically (same origin, same cookie). No extra auth wiring needed.
  • If you ever serve the Studio from a different origin, switch to ORDS REST + JWT. Not needed for the embedded pattern.

Step 4 — Iterating

To update the UI: edit FRP Studio.html here, re-upload to Static Application Files (overwrite). APEX bumps a cache-buster automatically. The host page doesn't need any changes.

★
Iframe vs. inline: If you'd rather the Studio inherit Universal Theme styling (and not be iframed), instead set the host page's region to HTML Expression and inline the file via #APP_FILES#FRP%20Studio.html served as a <link rel=stylesheet> for CSS + a <script> tag for JS. Iframe is safer because the Studio has its own full layout including a top bar — it'll fight Universal Theme's chrome.
