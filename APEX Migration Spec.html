P5 Bulk Upload Helper The 3,000-doc problem

OCI Console makes you upload one folder at a time. APEX page that accepts a multi-file drop, stages to APEX_APPLICATION_TEMP_FILES, and pushes to OCI in one go via DBMS_CLOUD.PUT_OBJECT in a background job.

  • File browse item with multiple attribute.
  • Region: queue table showing pending / uploaded / failed per file.
  • Background process via DBMS_SCHEDULER chains uploads → triggers FRP_INGEST.ingest_one per object.
  • Polling Dynamic Action refreshes the queue every 3s.

Schema additions needed

Three small additions to make the UI bindings clean:

-- Link table for "attached" docs on a proposal (currently mocked in UI)
CREATE TABLE FRP_PROPOSAL_ATTACHMENTS (
  PROPOSAL_ID  VARCHAR2(64) NOT NULL REFERENCES FRP_PROPOSALS,
  DOC_ID       VARCHAR2(64) NOT NULL REFERENCES FRP_DOCS,
  ROLE         VARCHAR2(32),  -- 'rfp' | 'reference' | 'template'
  ADDED_AT     TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (PROPOSAL_ID, DOC_ID, ROLE)
);

-- Ingest log so the UI can show which files failed and why
CREATE TABLE FRP_INGEST_LOG (
  LOG_ID       VARCHAR2(64) DEFAULT SYS_GUID() PRIMARY KEY,
  RUN_AT       TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  BUCKET_PATH  VARCHAR2(1024),
  STATUS       VARCHAR2(16),  -- 'OK' | 'FAILED' | 'SKIPPED'
  MESSAGE      VARCHAR2(4000)
);

-- Replace the hardcoded constant in FRP_INGEST
CREATE TABLE FRP_CONFIG (
  KEY          VARCHAR2(64) PRIMARY KEY,
  VALUE        VARCHAR2(1024)
);
